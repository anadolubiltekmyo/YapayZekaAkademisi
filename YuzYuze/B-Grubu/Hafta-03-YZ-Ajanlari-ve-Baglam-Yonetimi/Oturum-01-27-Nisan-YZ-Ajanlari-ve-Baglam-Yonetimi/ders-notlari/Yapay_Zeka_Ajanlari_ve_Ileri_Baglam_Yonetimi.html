Üç Nesil AI Kodlama: Autocomplete → Chat → Agent Three Generations

Geçen dönem boyunca vibe coding, full-stack web ve LLM API entegrasyonu derslerinde adım adım gördüğümüz şey aynı yönde ilerleyen bir AI asistan evrimi: önce satırı tamamlayan, sonra sohbet eden, şimdi ise kendi başına çalışan bir yardımcı. Bu hafta üçüncü nesle, agent çağına bakacağız.

Üç Nesil Tek Bakışta

1️⃣ AutocompleteTab ile satırı kabul etGitHub Copilot (eski sürüm), Tabnine, CodeiumSadece şu anki satırı görür; bağlamı dar.

🎯 Tek cümlede agent nedir? Agent, bir hedef aldığında kendi kararıyla dosya açan, terminal komutu çalıştıran, tarayıcıyı kontrol eden ve sonucu geri besleyen otonom bir döngüdür. Yani kod tamamlama yerine iş tamamlama.

Bütün modern agent'lar aşağıdaki şu beş adımı tekrarlar; insan müdahalesi her halkada mümkündür ama opsiyoneldir.

Önceki Derslerin Üstüne Ne Koyuyor?

  • Vibe coding (geçen hafta): "Doğal dilde anlat, AI yazsın." Agent çağı bunu "Anlat, AI hem yazsın hem çalıştırsın hem de düzeltsin"e çıkarıyor.
  • Full-stack web (2 hafta önce): Backend + frontend + deploy adımları paralel agent'larla aynı saatte tamamlanabiliyor.
  • LLM API (3 hafta önce): O dersteki tool use / function calling kavramı, agent'ların terminale, tarayıcıya, MCP sunucularına bağlanma şeklinin ta kendisi.
💡 Akılda Kalsın: Agent kullanmak prompt yazmaya benzer ama kapsam değişir. "Bana 2048 oyunu kodla" derseniz alırsınız; "Bana 2048 oyununu kodla, çalıştır, mobil görünümünü test et, ekran kaydı al" dediğinizde de alırsınız — fark, ikincisinin tek prompt'la bitebilmesi.

Antigravity Kurulum ve Politikalar Install & Policies

Antigravity, VS Code'un fork'u üzerine inşa edilmiş bir agent-first IDE. Apr 2026 itibarıyla preview aşamasında ve kişisel Gmail hesabıyla ücretsiz kullanılabiliyor (premium model kotaları ile birlikte).

Kurulum: 5 Dakikalık Adımlar

  1. antigravity.google/download üzerinden işletim sisteminize uygun paketi indirin (Mac, Windows, belirli Linux dağıtımları).
  2. Kurulumu çalıştırıp uygulamayı açın. İlk açılışta tema, keybindings (boş VS Code, Cursor ya da kendi tercihiniz), eklentiler ve agy CLI komutunu kurma seçenekleri çıkacak.
  3. Gmail ile giriş yapın — tarayıcıda yetkilendirme açılacak.
  4. Setup wizard'ında Review-driven development önerilen güvenli mod (aşağıda anlatılıyor).
  5. Dilerseniz mevcut VS Code/Cursor ayarlarınızı içe aktarabilirsiniz.
Antigravity kurulum sihirbazı — keybindings (boş, VS Code, Vim...), eklenti seti ve agy CLI kurulumu burada seçilir. Kaynak: Google Codelabs.

Üç Politika Üç Soru

Antigravity, agent'a verdiğiniz otonomi seviyesini üç ayrı politikayla kontrol eder. Bunlar setup'ta da, sonra Cmd+, ile de değiştirilebilir.

PolitikaSoruSeçenekler
Terminal ExecutionAgent komut çalıştırmadan önce sormalı mı?Always Proceed · Request Review
ReviewImplementation plan / task list ne zaman gözden geçirilsin?Always Proceed · Agent Decides · Request Review
JavaScript ExecutionBrowser subagent JS çalıştırabilsin mi?Always Proceed · Request Review · Disabled

Hazır Profiller

Bu üç politikayı tek tek seçmek yerine 4 hazır profilden birini de seçebilirsiniz:

  • 🛡️ Secure Mode — En kısıtlayıcı. Yeni başlayanlar ve hassas projeler için.
  • 🤝 Review-driven development (önerilen) — Agent karar verir ama kritik anlarda onay ister.
  • 🚀 Agent-driven development — Agent hiç sormaz; en hızlı ama en riskli.
  • ⚙️ Custom configuration — Üç politikayı tek tek kendiniz ayarlarsınız.
⚠️ Yeni Başlayan İçin Tavsiye: İlk hafta Review-driven ile başlayın. Agent'ın hangi komutları çalıştırmak istediğini gördükçe ona güvenmeniz veya güvenmemeniz için sezginiz oluşur. Agent-driven'a geçmek için "ben hangi komutların güvensiz olduğunu biliyorum" hissi gerekir; bu bir hafta sonra gelir.

İlk Çalıştırma Sonrası Kontrol Listesi

  • ✅ Bir proje klasörü açtınız mı? (Workspace)
  • ✅ Bir Model seçtiniz mi? (Gemini 3 Pro, 2.5, vb.)
  • ✅ Planning mode mı Fast mode mı?
  • ✅ Dil/framework eklentileri kurulu mu? (Python, Go, Rust...)
  • ✅ Git'i bağladınız mı? (Çoğu agent .git varsa daha iyi karar veriyor.)

Mission Control: Agent Manager Mission Control

Antigravity'nin diğer IDE'lerden en belirgin farkı, açılışta sizi karşılayan ekrandır: dosya ağacı değil, Agent Manager. Buraya Mission Control da deniyor; agent'larınızın "kontrol kulesi" gibi düşünebilirsiniz.

Antigravity'yi ilk kez açtığınızda sizi karşılayan ekran — dosya ağacı yerine doğrudan Agent Manager. Bu, IDE'nin kasıtlı bir tasarım kararı: kod yazmadan önce agent'ı yönetin.

Mission Control'de Tipik Bir Akış

  1. Workspace'i seç (örn. ~/projects/oyun-jam-2026).
  2. Model: Gemini 3 Pro, Mode: Planning.
  3. Promptu yaz ve Enter'a bas:

"Pygame ile basit bir uzay savaşı oyunu yap: 800x600 pencere, oyuncu altta, 5 sıra düşman, ateş ve skor. Pyinstaller ile macOS .app paketi de oluştur ve dist/ klasörüne yerleştir. Walkthrough'da çalışan oyunun ekran görüntüsünü ekle."

  1. Agent Implementation Plan üretir → onaylarsınız.
  2. Task list çıkar → buna da yorum ekleyebilirsiniz ("test sırasında 3 farklı düşman dalgası dene").
  3. Agent kodu yazar, terminalden çalıştırır, ekran görüntüsünü walkthrough'a ekler. Siz başka bir tab'da başka bir görevi paralel başlatabilirsiniz (8. bölüm).
💡 Workspace ≠ Aktif Klasör: Aynı anda birden fazla workspace açıkken Antigravity hangi klasörde dosya yaratacağını workspace seçimine göre yapar. Yanlış workspace'te konuşma açıp kodu başka projeye yazdırmak en sık yapılan hatalardan biridir; ilk satırda "which workspace?" yorumunu görene kadar dikkat edin.

Antigravity Browser Subagent Browser Subagent

Antigravity'nin sıra dışı yanlarından biri, tarayıcıyı kontrol edebilen ayrı bir alt-ajanı olması. Bu subagent kendi modeliyle çalışır: tıklar, scroll yapar, klavyeyi tuşlar, console log'u okur, DOM'u görür ve hatta video kaydı alır.

Ne İşe Yarıyor? (Önceki Derslerle Bağ)

  • Vibe coding oyununu test etmek: Geçen hafta yaptığımız p5.js oyununu agent açıp tıklatarak skor sayacının arttığını doğrulayabilir.
  • Full-stack login akışı: 2 hafta önceki Flask uygulamasında "kullanıcı kayıt → giriş → dashboard" yolunu video kaydıyla doğrulamak.
  • LLM API stream UI: 3 hafta önceki streaming chatbot için "kullanıcı mesaj yazsın, ekranda token token görünsün" akışının regression testini yapmak.

Kurulum

  1. Bir konuşmada agent'a tarayıcı görevi verin: "go to antigravity.google".
  2. Agent Setup browser subagent butonu çıkaracak.
  3. Açılan Chrome'da Antigravity uzantısını yükleyin.
  4. Chrome size izin sorduğunda izin verin.
Agent tarayıcı işine ihtiyaç duyduğunu fark ettiğinde böyle bir Setup butonu çıkarır — tıkladığınızda Chrome açılıp Antigravity uzantısının kurulum sürecini başlatır.
Chrome'da açılan Add to Chrome sayfası — Antigravity browser uzantısı buradan kurulur. Kurulum sonrası Chrome agent için Antigravity profili olarak çalışır.
Uzantı yüklendikten sonra Agent Manager'a döndüğünüzde agent'ın tarayıcı işlemine başlamak için izin beklediğini görürsünüz — onayladığınızda devam eder.
İzin verildikten sonra agent antigravity.google sayfasına güvenli şekilde gitti; ekran görüntüsü ve video kaydı artifact olarak Mission Control'a düşer.

Browser Subagent İçin Somut Promptlar

"localhost:5000 adresinde çalışan FastAPI todo uygulamasını aç. Şu adımları sırayla yap: 1) 'Süt al' başlıklı bir görev ekle 2) 'Yumurta al' başlıklı bir görev ekle 3) Birinci görevi 'tamamlandı' olarak işaretle 4) Tüm akışı 30 saniyelik browser recording olarak kaydet 5) Walkthrough'a ekle"

"Tarayıcıda https://kaplay-snake-demo.netlify.app adresine git. Yılan oyununu 60 saniye otomatik oyna (rastgele yön tuşlarına bas). Konsoldaki hataları topla, son skoru kaydet ve raporla."

⚠️ JavaScript Execution Policy Browser subagent JS çalıştırabiliyor. Eğer agent güvensiz bir siteye yanlışlıkla giderse XSS / prompt injection vektörü açılabilir. Hassas projelerde JS'i Disabled, deneme projelerinde Request Review tutmak iyi bir pratiktir. Ayrıca 14. bölümde bahsedilen Browser URL Allowlist'i kullanın.

Tipik bir Antigravity editor düzeni: solda dosya ağacı, ortada editör, altta terminal (Ctrl + `), sağda agent yan paneli (Cmd + L).

Editor İçi Akıllı Davranışlar

  • Smart autocomplete — Yazarken AI önerisi gelir, Tab ile kabul.
  • Tab to import — Import edilmemiş bir sembol kullandığınızda Tab import'u ekler.
  • Tab to jump — Bir sonraki mantıklı satıra atlar (örn. fonksiyon gövdesinden return'e).

Hata Üzerinden Tek Tıkla Çözüm

  • Hover üstüne Explain and fix: Linter hatasında üzerine gel, "Açıkla ve düzelt" butonu agent'a gönderir.
  • Problems panelinde Send all to Agent: Tüm linter sorunlarını topluca agent'a havale.
  • Terminal çıktısı seçip Cmd+L: Stack trace'i agent'a yapıştırır.
Terminal çıktısının bir kısmını seçip Cmd+L ile agent yan paneline yapıştırırsınız — stack trace'i kopyala/yapıştır yapmanız gerekmez.
Agent yan paneli: @ ile dosya/dizin/MCP context'i eklenir, / ile kayıtlı workflow'lar autocomplete olarak listelenir.
💡 Cursor Kullanıcıları İçin Önemli Not: Antigravity'de Cmd+E editor ↔ Mission Control toggle'ıdır. Cursor'da aynı kısayol Background Agent başlatır (8. bölümde detaylı). Aynı tuş, farklı mantık — IDE'ler arası geçiş yaparken kafa karıştırabilir.

⌨️ Cursor'da Cmd+E ile Background Agent

Cursor 1.0'dan beri (Haziran 2025) Cmd+E Composer'ı Background Agent'a çevirir. Görev tarayıcıyı engellemeden arka planda çalışır; siz başka iş yapmaya devam edebilirsiniz.

  1. Composer'ı aç: Cmd+I

Feedback Döngüsü: Todo App Demo'su Feedback Loop

Antigravity codelab'inin "Provide Feedback" bölümü, agent'a iş verdikten sonra nasıl yön vereceğinizi en iyi gösteren örnektir. Burada yaptığı şey aslında geçen haftaki vibe coding dersinde tek tek elle yapmak zorunda kaldığımız iterasyonların artifact üzerinden formalize edilmiş hali.

Senaryo: Basit Todo App'i Geliştirme

Codelab şu prompt'la başlıyor:

"Build a simple to-do app using Python (Flask)."

Agent Implementation Plan üretiyor: Flask backend, Jinja2 template, in-memory liste, vb. Şimdi 3 tipik feedback tipini görelim.

1) Implementation Plan'a Yorum: Mimari Değişiklik

Flask iyi ama dersin geri kalanında FastAPI kullanacaksak baştan onu seçelim. Plan üzerinde "Flask" kelimesini seçip yorum kutusuna:

"Flask yerine FastAPI kullan. Endpoint stilini RESTful yap (GET /todos, POST /todos, PATCH /todos/{id}). Pydantic ile request body validation ekle. Test için pytest+httpx kur."

Agent planı yeniden yazar — sadece Flask satırlarını değil, ona bağımlı kararları da (template engine, deploy adımları) günceller.

2) Code Diff'e Yorum: Tema/UX Değişikliği

Editor'daki Review Changes ekranında değişen satırlara doğrudan yorum bırakarak agent'tan revize isteyebilirsiniz.

"Mavi tema yerine 'sıcak' bir palet kullan: arka plan amber-50 (#fffbeb), butonlar orange-600 (#ea580c), başlıklar zinc-900. Hover state'lerinde %10 koyulaşma efekti ekle. Tüm CSS'i tek dosyada (style.css) tut."

3) Walkthrough Yorumu: Yeni Davranış

Görev bittiğinde agent Walkthrough üretir: değişikliklerin özeti, ekran görüntüleri ve doğrulama yönergeleri. Bu artifact üzerinden de yeni davranış talep edebilirsiniz:

"Walkthrough'da gördüğüm akışta 'tamamlandı' işaretini yanlışlıkla atan kullanıcı için 'undo' butonu yok. Son işaretlemeyi 5 saniye için geri alabilen bir snackbar ekle. 5 sn sonra otomatik kaybolsun. Bu davranışı testle de doğrula."

Feedback Yazarken 4 Altın Kural

  1. Spesifik ol — "Daha güzel" değil, "#ea580c".
  2. Gerekçe ekle — "Çünkü dersin geri kalanı FastAPI kullanıyor." Agent gerekçeyi sonraki promtlarda da kullanır.
  3. Bir seferde 1 değişiklik — 5 maddeli yorum agent'ı hangi maddeden başlayacağı konusunda tereddüde sokar.
  4. Doğrulama iste — "Test ekle", "ekran görüntüsü al". Doğrulama olmayan değişiklik gelecekte regresyon olarak gelir.
↩️ Undo Süper Gücü Antigravity her artifact'a kadar geri dönmenize izin verir. "Beğenmedim" demek yerine eski versiyonu seçip oradan farklı bir feedback verebilirsiniz. Bu, geçen haftaki "kötü prompt sonrası 50 satır kodu temizleyemiyorum" derdine bir çözüm.

# .agents/rules/python-style.md --- description: Bu workspace için Python kod stili --- - Tüm modüller type hint kullansın (PEP 604: `int | None`). - 80 karakter satır limiti, ruff-format ile. - Fonksiyonlar 50 satırı geçmesin; geçecekse parçala. - Print yerine `logging` modülü, `logger = logging.getLogger(__name__)`. - Async I/O: `asyncio` + `httpx.AsyncClient`. `requests` kütüphanesi yasak. - Test framework: pytest. # .agents/workflows/generate-unit-tests.md --- description: Bir Python modülü için pytest test setini üret auto_execution_mode: interactive --- # Adımlar 1. Hedef dosyanın yolunu sor (varsa, kullanıcı argüman vermişse atla). 2. `pip show pytest` çıktısını kontrol et; yoksa `pip install pytest pytest-cov` çalıştır. 3. Modülün public fonksiyonlarını listele. 4. Her fonksiyon için en az 3 vaka üret: (a) tipik, (b) sınır durum, (c) hatalı input. 5. Test dosyasını `tests/test_{modül_adı}.py` olarak yaz. 6. `pytest --cov=. tests/` çalıştır, coverage raporunu paylaş. 7. Coverage <%80 ise eksik branchlar için ek test öner. 8. Walkthrough'a coverage özetini ekle.

Çağırmak için: konuşma kutusuna /generate-unit-tests src/payment.py.

Skills: Progressive Disclosure Skills

Skill, agent'ın ihtiyaç duyduğunda yükleyeceği bağımsız bir bilgi paketidir: bir SKILL.md dosyası, opsiyonel scriptler ve kaynaklar. Her zaman context'te değildir; başlığı + açıklaması taranır, görev uyarsa içerik açılır. Buna progressive disclosure deniyor.

Neden Skill? — Tool Bloat Problemi

Hayal edin: agent'a 50 farklı görevi yapabilen 50 yetenek vermek istiyorsunuz. Hepsini her promptta context'e koyarsanız:

  • 📈 Token tüketimi 10 katına çıkar
  • 🎯 Agent yanlış yetenek seçer çünkü hepsi aynı anda görünür
  • ⏳ İlk yanıt gecikmesi artar

Skills bunu çözer: agent başlangıçta sadece her skill'in 1-2 satırlık "ne işe yarar" bilgisini görür. İhtiyaç olunca tam içeriği yükler.

Şemaya birebir uyan, sadece JSON üreterek tekrar gönder."}) raise RuntimeError(f"Validation failed after {max_retries+1} tries: {last_err}") ``` ## Örnek Kullanım ```python from pydantic import BaseModel, Field class Recipe(BaseModel): title: str ingredients: list[str] = Field(min_length=1) steps: list[str] = Field(min_length=1) cook_time_minutes: int recipe = await validated_call(client, Recipe, "Bana basit bir mercimek çorbası tarifi ver") print(recipe.model_dump_json(indent=2)) ```

Pratikte Karşılaşılan Tipik Hatalar Common Pitfalls

Bu hafta agent kullanmaya başlayanların ilk birkaç günde yaşadığı, vakit yiyen, moral bozan tipik hatalar. Hepsinin çözümü kısa ve basit.

🛑 Hata 1: İki Agent Aynı Dosyaya Yazıyor

  • Belirti: Agent A backend'de değişiklik yaparken Agent B aynı dosyada başka bir şey yapıyor; merge conflict patlıyor.
  • Çözüm: /worktree kullanın (Cursor 3.0) ya da agent'ları farklı branch'lere açıkça yönlendirin: "feature/auth branch'ine geç ve sadece app/auth/ altına yaz".

🛑 Hata 2: Planning Mode Yerine Fast Mode Seçmek

  • Belirti: "Bana e-ticaret sitesi yap" dediniz, agent direkt hızlıca yarım yamalak bir sayfa açtı.
  • Çözüm: Yeni feature, refactor veya keşif gerektiren her görev için Planning Mode. Fast Mode sadece "değişken yeniden adlandır", "tek satır düzelt" için.

🛑 Hata 3: Allow List Olmadan git push Bekleyince

  • Belirti: Agent "değişiklikler push edildi" dedi ama remote'da yok.
  • Çözüm: Allow list'inizi kontrol edin; git push * içinde mi? Çoğu IDE security default'ta push'u onaya bırakır.

🛑 Hata 4: SKILL.md Description'ı Çok Genel

  • Belirti: Skill kuruldu ama hiç tetiklenmiyor; veya yanlış skill tetikleniyor.
  • Çözüm: Description'ı somut tetikleyici kelimelerle zenginleştirin: "kod review et", "PR incele", "değişiklikleri kontrol et". "Code review" tek başına yetmez.

🛑 Hata 5: Premium Token Bütçesini Tek Promptta Yakmak

  • Belirti: Gemini 3 Pro premium kotanız 30 dakikada bitti.
  • Çözüm: Keşif için Gemini Flash veya Claude Haiku kullanın; sadece final implementation için pro modele geçin. /best-of-n komutu da pahalıdır — sadece kritik kararlarda.

🛑 Hata 6: Yanlış Workspace'e Konuşma Açmak

  • Belirti: Tatil projeniz için söylediğiniz şeyleri agent okul ödevinizin reposuna yazdı.
  • Çözüm: Mission Control'de aktif workspace'i ekranın üstüne sabitleyin; her yeni konuşmada bir kez doğrulayın.

🛑 Hata 7: "Test Yaz" Demeden İterasyon

  • Belirti: 5 iterasyon sonra A çalışıyor ama B kırıldı; tekrar düzeltmek 3 saat aldı.
  • Çözüm: İlk feature için bile minimum 1 pytest yazdırın. Sonraki iterasyonda "değişikliği test et" demek bedavadır.

🛑 Hata 8: Browser Subagent'ı Internetten Erişimle Kullanmak

  • Belirti: Browser subagent rastgele tutorial sitesinde gezerken talimat alıp gizlice agent'a yanlış komut verdi.
  • Çözüm: Browser URL allowlist'i sıkı tutun. Localhost + bilinen doc siteleri ile sınırlayın.
📊 Pratik Metrik Yeni başlayanların ilk haftası şuna benzer: "5 görev aç, 2'si başarısız, 3'ü çalışır." Üçüncü hafta: "5 görev aç, 4'ü çalışır, 1'i biraz iterasyon." Bu doğru bir öğrenme eğrisi. İlk haftaki hatalar normaldir; not bile alın, ileride skill'lere ya da rule'lara dönüştürün.
