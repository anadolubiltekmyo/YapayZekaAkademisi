Statik vs Dinamik Web Sayfaları Static vs Dynamic Web Pages

Bir web sitesini ziyaret ettiğinizde tarayıcınız (Chrome, Firefox, Safari…) bir sunucuya istek gönderir ve gelen yanıtı ekranınızda gösterir. Ama tüm web siteleri aynı şekilde çalışmaz. İki temel kategori vardır:

📄 Statik Web Sayfası

  • Sunucuda hazır HTML/CSS/JS dosyaları bulunur
  • Her kullanıcıya aynı içerik gönderilir
  • Sunucu tarafında işlem yapılmaz
  • Blog, portfolyo, tanıtım sitesi için ideal
  • GitHub Pages ile ücretsiz yayınlanabilir

⚡ Dinamik Web Sayfası

  • Sunucu, her istekte içeriği üretir
  • Kullanıcıya özel sayfalar gösterilir
  • Veritabanından veri çekilir, formlar işlenir
  • E-ticaret, sosyal medya, dashboard için gerekli
  • Bir backend sunucusu gerektirir

Gerçek Dünya Örnekleri

Web SitesiTürNeden?
Kişisel blogStatikHer ziyaretçi aynı içeriği görür
WikipediaDinamikArama yapılır, sayfa sunucu tarafında üretilir
Online mağazaDinamikKullanıcı girişi, sepet, ödeme var
Firma tanıtım sayfasıStatikİletişim formu dışında sabit içerik
Öğrenci not sistemiDinamikHer öğrenci kendi notlarını görür
💡 Hatırlatma: Statik siteler çok daha kolay ve ucuz yayınlanır — GitHub Pages, Netlify, Vercel gibi platformlarda ücretsiz barındırılabilir. Ancak kullanıcı girişi, veri kaydetme gibi işlemler gerektiriyorsanız dinamik bir yapıya (backend + veritabanı) ihtiyacınız var demektir.

Hangisini Seçmeliyim?

Kendinize şu soruyu sorun: "Kullanıcılar siteye veri kaydedecek mi?"

  • Hayır → Statik site yeterli (blog, portfolyo, dokümantasyon)
  • Evet → Dinamik site gerekli (kullanıcı girişi, CRUD işlemleri, dashboard)

Veri Saklama Yolları Data Storage Methods

Bir web uygulamasında kullanıcı verilerini saklamanın birkaç farklı yolu vardır. Her birinin kendine özgü avantajları ve sınırlamaları var. Bunları basitten karmaşığa doğru inceleyelim:

🍪 Cookie (Çerez)

Cookie, tarayıcıda saklanan küçük metin parçalarıdır (en fazla ~4 KB). Sunucu tarafından ayarlanabilir ve her istekle birlikte sunucuya otomatik gönderilir.

  • Kullanım: Oturum yönetimi (session), dil tercihi, "beni hatırla" seçeneği
  • Avantaj: Sunucu ile otomatik paylaşılır
  • Dezavantaj: Çok küçük (4 KB), her istekte gönderilir (performans), güvenlik riskleri (XSS)
// Cookie oluşturma (JavaScript)
document.cookie = "tema=koyu; max-age=86400; path=/";

// Cookie okuma
console.log(document.cookie); // "tema=koyu"

💾 localStorage & sessionStorage

Tarayıcıda veri saklamanın modern yolu. Cookie'den çok daha büyük alan sunar (~5-10 MB).

🗄️ Veritabanı (Database)

Gerçek uygulamalar için en doğru çözüm veritabanıdır. Veritabanı, verilerin sunucu tarafında düzenli şekilde saklandığı bir sistemdir.

  • Verilere tüm cihazlardan erişilir (telefon, tablet, laptop…)
  • Büyük miktarda veri saklanabilir (milyonlarca kayıt)
  • Veriler güvenli şekilde korunur (yetkilendirme)
  • Aynı anda binlerce kullanıcı erişebilir
⚠️ Önemli Fark: Cookie ve localStorage verileri sadece o tarayıcıda bulunur. Kullanıcı farklı bir cihazdan girdiğinde veriler görünmez. Telefonunuzu değiştirseniz veya tarayıcı verisini temizleseniz her şey kaybolur. Veritabanı ise sunucuda durur — her yerden erişilebilir, kalıcı ve güvenlidir.

  • Basit tercihler (tema, dil) → localStorage
  • Oturum/giriş bilgisi → Cookie (HttpOnly, sunucu tarafı)
  • Kullanıcı verileri, iş verileri → Veritabanı

Veritabanı Temelleri Database Fundamentals

Veritabanı (database) verilerin düzenli biçimde saklandığı, aranabildiği ve yönetilebildiği bir sistemdir. Bunu bir Excel tablosu gibi düşünebilirsiniz — ama çok daha güçlü, çok daha hızlı ve çok sayıda kullanıcıya aynı anda hizmet verebilen bir yapı.

📋 Tablo (Table) Nedir?

Veritabanının temel yapı taşı tablodur. Her tablo, belirli bir veri türünü (kullanıcılar, ürünler, siparişler…) düzenli satır ve sütunlar halinde saklar:

Örnek: kullanicilar tablosu

idademailsifre_hashkayit_tarihi
1Ayşe Yılmazayse@email.com$2b$10$xK…2026-04-01
2Mehmet Demirmehmet@email.com$2b$10$pQ…2026-04-05
3Zeynep Karazeynep@email.com$2b$10$rT…2026-04-10
  • Satır (Row / Record): Tek bir kayıt — örneğin bir kullanıcı
  • Sütun (Column / Field): Bir özellik — örneğin "email" veya "ad"
  • id: Her satırı benzersiz tanımlayan numara (Primary Key)

🔗 İlişkiler (Relations)

Tablolar birbirleriyle ilişkilendirilebilir. Örneğin bir e-ticaret sitesinde:

  • kullanicilar tablosu → Kullanıcı bilgileri
  • siparisler tablosu → Her sipariş, hangi kullanıcıya ait olduğunu belirtir

Örnek: siparisler tablosu

idkullanici_iduruntutartarih
1011Laptop25000 ₺2026-04-12
1021Mouse500 ₺2026-04-12
1033Klavye1200 ₺2026-04-13

Burada kullanici_id sütunu, kullanicilar tablosundaki id ile eşleşir. Bu bir Foreign Key (yabancı anahtar) ilişkisidir. Sayesinde "Ayşe'nin siparişleri neler?" sorusunu cevaplayabiliriz.

📝 SQL ile Temel İşlemler (CRUD)

SQL (Structured Query Language), veritabanıyla konuşmak için kullanılan dildir. Dört temel işlem vardır — kısaca CRUD:

İşlemSQL KomutuAnlamı
CreateINSERT INTOYeni kayıt ekle
ReadSELECTVeri oku / listele
UpdateUPDATEMevcut kaydı güncelle
DeleteDELETEKayıt sil
-- Yeni kullanıcı ekle (Create)
INSERT INTO kullanicilar (ad, email) VALUES ('Ali Can', 'ali@email.com');

-- Tüm kullanıcıları listele (Read)
SELECT * FROM kullanicilar;

-- Belirli kullanıcının emailini güncelle (Update)
UPDATE kullanicilar SET email = 'yeni@email.com' WHERE id = 1;

-- Kullanıcı sil (Delete)
DELETE FROM kullanicilar WHERE id = 2;

-- Ayşe'nin siparişlerini getir (İlişkisel sorgu)
SELECT s.urun, s.tutar
FROM siparisler s
JOIN kullanicilar k ON s.kullanici_id = k.id
WHERE k.ad = 'Ayşe Yılmaz';

Bulut Tabanlı Veritabanları Cloud Databases

Veritabanı kullanmak normalde bir sunucu kurmayı, yazılımı yüklemeyi ve yönetmeyi gerektirir. Ancak bugün bulut tabanlı (cloud-hosted) veritabanları sayesinde bunların hiçbirini yapmadan, dakikalar içinde çalışan bir veritabanına sahip olabilirsiniz. Bunlara bazen BaaS (Backend as a Service) de denir.

🔥 Firebase (Google)

Google'ın geliştirdiği, en popüler BaaS platformu. Ücretsiz planı oldukça cömerttir. Veritabanı olarak Firestore (NoSQL) sunar.

  • ✅ Ücretsiz katman (Spark planı): 1 GB depolama, 50.000 okuma/gün
  • ✅ Gerçek zamanlı veri senkronizasyonu
  • ✅ Kolay kullanıcı kimlik doğrulama (Auth)
  • ✅ Dosya depolama (Storage)
  • ⚠️ NoSQL — karmaşık sorgular zor olabilir

🔗 firebase.google.com

⚡ Supabase

"Açık kaynak Firebase alternatifi" olarak bilinen Supabase, arka planda PostgreSQL (SQL) kullanır. SQL seven geliştiriciler için ideal.

  • ✅ Ücretsiz katman: 500 MB depolama, 2 proje
  • ✅ Gerçek SQL veritabanı (PostgreSQL)
  • ✅ Otomatik REST API oluşturma
  • ✅ Yerleşik Auth sistemi
  • ✅ Real-time abonelikler

🔗 supabase.com

📦 PocketBase

Tek dosyada çalışan, kendi sunucunuza kurulabilen açık kaynak backend. SQLite tabanlıdır.

  • ✅ Tamamen ücretsiz ve açık kaynak
  • ✅ Tek çalıştırılabilir dosya — kurulum gerektirmez
  • ✅ Admin paneli dahili
  • ✅ Auth, dosya depolama, real-time dahil
  • ⚠️ Çok büyük ölçekli projeler için uygun değil

🔗 pocketbase.io

Frontend ve Backend Ayrımı Frontend vs Backend

Bir web uygulaması iki ana bölümden oluşur: Frontend (kullanıcının gördüğü) ve Backend (kullanıcının görmediği, sunucu tarafı). Bu ayrımı bir restoran örneğiyle anlayalım:

Frontend — Ön Uç

Kullanıcının doğrudan gördüğü ve etkileştiği kısımdır:

  • HTML: Sayfanın yapısı (başlık, paragraf, buton, form…)
  • CSS: Sayfanın görünümü (renkler, yazı tipleri, düzen…)
  • JavaScript: Sayfanın davranışı (tıklama, animasyon, veri gönderme…)

Modern frontend geliştirmede genellikle framework (çerçeve) kullanılır: React, Vue.js, Svelte, Angular gibi. Bu çerçeveler, büyük arayüzleri bileşenler (components) halinde organize etmenizi sağlar.

Backend — Arka Uç

Kullanıcının görmediği, sunucu tarafında çalışan kısımdır:

  • Kullanıcı girişi ve oturum yönetimi
  • Veritabanı okuma/yazma işlemleri
  • İş mantığı (fiyat hesaplama, e-posta gönderme…)
  • API (Application Programming Interface) sunma
  • Güvenlik kontrolleri

API: İkisini Birbirine Bağlayan Köprü

Frontend ve backend, API aracılığıyla iletişim kurar. Frontend bir istek gönderir (örneğin "kullanıcı listesini getir"), backend bu isteği işler ve sonucu JSON formatında döner: 

// Frontend'den backend'e istek gönderme (fetch API)
const yanit = await fetch("https://api.example.com/kullanicilar");
const kullanicilar = await yanit.json();

// Backend'in döndürdüğü JSON yanıt:
[
  { "id": 1, "ad": "Ayşe", "email": "ayse@email.com" },
  { "id": 2, "ad": "Mehmet", "email": "mehmet@email.com" }
]
💡 Full-Stack Nedir? Hem frontend hem backend geliştirme yapabilen kişiye Full-Stack Developer denir. Bu derste amacımız vibe coding ile her iki tarafı da AI'a yazdırmak — ama hangi parçanın ne işe yaradığını bilmeniz, AI'a doğru talimat vermenizi sağlar.

Vibe Coding ile CRUD Uygulaması Building a CRUD App

CRUD, her web uygulamasının temelinde yatan dört işlemdir: Create (oluştur), Read (oku), Update (güncelle), Delete (sil). Bir görev listesi (todo), not defteri, adres defteri — hepsi aslında birer CRUD uygulamasıdır.

Adım Adım: Görev Yönetim Uygulaması

1. Adım — Projeyi Tanımlayın

"React + Node.js + Express + SQLite kullanarak bir görev yönetim (todo) uygulaması oluştur. Şu özellikler olsun:

- Yeni görev ekleme (başlık + açıklama)
- Görevleri listeleme
- Görevi tamamlanmış olarak işaretleme
- Görevi silme
- Görev düzenleme

Backend'de Express ile REST API oluştur. Frontend temiz ve modern görünsün, Tailwind CSS kullan."

2. Adım — Veritabanını Ekleyin

"Veritabanında 'tasks' tablosu olsun. Sütunlar: id (otomatik artan), title (metin), description (metin), completed (boolean, varsayılan false), created_at (tarih). SQLite kullanarak veritabanını oluştur ve backend API'lerini bu tabloya bağla."

3. Adım — Arayüzü İyileştirin

"Görev listesine tarih filtreleme ekle. Ayrıca tamamlanmış görevler üzeri çizili görünsün. Ekranın üstüne toplam görev sayısı ve tamamlanan görev sayısını gösteren bir özet kutusu ekle."

4. Adım — Hataları Düzeltin

"Görev ekleme formunda boş başlık gönderme engellensin. Backend'de de validasyon yap — başlık boşsa 400 hata kodu dönsün. Frontend'de kullanıcıya Türkçe hata mesajı göster."

🎯 Vibe Coding'in Altın Kuralı: Tek seferde her şeyi istemeyin. Küçük adımlarla ilerleyin: önce temel yapıyı oluşturun, sonra özellik ekleyin, sonra görünümü iyileştirin. Her adımda sonucu test edin, çalışıyorsa bir sonraki adıma geçin.

Basit Bir CRUD API Neye Benzer?

// Express.js ile basit REST API örneği
const express = require('express');
const app = express();
app.use(express.json());

let gorevler = []; // Veritabanı yerine geçici dizi
let sonrakiId = 1;

// CREATE - Yeni görev ekle
app.post('/api/gorevler', (req, res) => {
  const gorev = {
    id: sonrakiId++,
    baslik: req.body.baslik,
    tamamlandi: false
  };
  gorevler.push(gorev);
  res.status(201).json(gorev);
});

// READ - Tüm görevleri listele
app.get('/api/gorevler', (req, res) => {
  res.json(gorevler);
});

// UPDATE - Görevi güncelle
app.put('/api/gorevler/:id', (req, res) => {
  const gorev = gorevler.find(g => g.id === parseInt(req.params.id));
  if (!gorev) return res.status(404).json({ hata: 'Görev bulunamadı' });
  gorev.baslik = req.body.baslik || gorev.baslik;
  gorev.tamamlandi = req.body.tamamlandi ?? gorev.tamamlandi;
  res.json(gorev);
});

// DELETE - Görevi sil
app.delete('/api/gorevler/:id', (req, res) => {
  gorevler = gorevler.filter(g => g.id !== parseInt(req.params.id));
  res.status(204).send();
});

app.listen(3000, () => console.log('Sunucu 3000 portunda çalışıyor'));
💡 REST API Nedir? REST, web üzerinde veri alışverişi için kullanılan bir mimari stildir. Her veri kaynağı (görevler, kullanıcılar…) bir URL ile temsil edilir. HTTP metotları ile işlem yapılır: GET (oku), POST (oluştur), PUT (güncelle), DELETE (sil).

Giriş Yöntemleri

1. Email + Şifre (Klasik)

En yaygın yöntem. Kullanıcı email ve şifre ile kayıt olur, giriş yapar.

  • Şifre asla düz metin (plain text) olarak saklanmaz!
  • Şifre hash'lenerek (bcrypt, argon2) saklanır
  • Giriş sırasında girilen şifrenin hash'i, veritabanındaki hash ile karşılaştırılır
// Node.js'de şifre hash'leme (bcrypt)
const bcrypt = require('bcrypt');

// Kayıt sırasında — şifreyi hash'le
const hash = await bcrypt.hash("kullanici_sifresi", 10);
// Sonuç: "$2b$10$xKq3JZx..." gibi bir hash

// Giriş sırasında — hash'i kontrol et
const eslesme = await bcrypt.compare("girilen_sifre", hash);
// true veya false döner

2. OAuth — Sosyal Giriş (Google, GitHub, Apple…)

Kullanıcı kendi şifresini oluşturmak yerine, mevcut bir hesabıyla (Google, GitHub vb.) giriş yapar. Bu yönteme OAuth 2.0 denir.

OAuth avantajları:

  • Kullanıcı yeni şifre hatırlamak zorunda kalmaz
  • Siz şifre saklamak zorunda kalmazsınız (güvenlik artışı)
  • Kayıt/giriş süreci çok daha hızlı

3. JWT (JSON Web Token)

Kullanıcı giriş yaptıktan sonra, sunucu bir token (jeton) üretir ve kullanıcıya gönderir. Kullanıcı sonraki isteklerde bu token'ı göndererek kimliğini kanıtlar. Token'ın içinde kullanıcı bilgisi şifrelenmiş olarak bulunur. 

// JWT token oluşturma (Node.js)
const jwt = require('jsonwebtoken');

// Giriş başarılı → token üret
const token = jwt.sign(
  { id: kullanici.id, email: kullanici.email },
  process.env.JWT_SECRET,       // Gizli anahtar (.env dosyasında)
  { expiresIn: '24h' }          // 24 saat geçerli
);

// Frontend bu token'ı her istekte gönderir:
// Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

"React + Express ile kullanıcı giriş sistemi yap. Email/şifre ile kayıt ve giriş olsun. Şifreleri bcrypt ile hashle. JWT token ile oturum yönet. Ayrıca Google OAuth ile giriş seçeneği ekle (passport.js kullan). Giriş yapmamış kullanıcılar dashboard sayfasına erişemesin."

⚠️ Kritik Güvenlik Kuralları:
  • Şifreleri asla düz metin olarak veritabanına kaydetmeyin
  • JWT secret'ını .env dosyasında saklayın, koda yazmayın
  • .env dosyasını asla GitHub'a yüklemeyin (.gitignore'a ekleyin)
  • HTTPS kullanın — şifrelerin ağ üzerinden şifresiz gitmesini önleyin

Güvenlik: Bilinmesi Gerekenler Web Security Essentials

Web uygulamalarında güvenlik, sonradan eklenen bir özellik değil, baştan düşünülmesi gereken bir zorunluluktur. Vibe coding ile uygulama geliştirirken bile şu temel güvenlik konularını bilmelisiniz:

💉 SQL Injection (SQL Enjeksiyonu)

Saldırgan, form alanlarına SQL kodu yazarak veritabanınıza müdahale eder. Dünyanın en yaygın web güvenlik açığıdır.

❌ Kötü Örnek (Asla böyle yapmayın!)

// TEHLIKE! Kullanıcı girişi doğrudan SQL sorgusuna ekleniyor
const query = `SELECT * FROM kullanicilar 
               WHERE email = '${req.body.email}' 
               AND sifre = '${req.body.sifre}'`;
// Kullanıcı email alanına: ' OR '1'='1 yazarsa TÜM kullanıcıları getirir!

✅ Doğru Yol: Parametreli Sorgular (Prepared Statements)

// GÜVENLİ: Parametreli sorgu kullanımı
const query = `SELECT * FROM kullanicilar WHERE email = ? AND sifre_hash = ?`;
db.run(query, [req.body.email, hash], (err, row) => {
  // Kullanıcının girdiği değerler otomatik olarak temizlenir (escape edilir)
});

🕸️ XSS (Cross-Site Scripting)

Saldırgan, bir forma veya URL'ye JavaScript kodu ekler. Bu kod diğer kullanıcıların tarayıcısında çalışır ve cookie'lerini çalabilir.

❌ Kötü Örnek

// Kullanıcının girdiği metin doğrudan HTML'e ekleniyor
document.innerHTML = kullaniciYorumu; 
// Kullanıcı yorum alanına: <script>document.cookie</script> yazabilir!

✅ Doğru Yol

// textContent kullanarak HTML çalıştırılmasını engelle
element.textContent = kullaniciYorumu;

// Veya DOMPurify gibi bir kütüphane ile temizle
import DOMPurify from 'dompurify';
element.innerHTML = DOMPurify.sanitize(kullaniciYorumu);

🚧 CORS Nedir? (Cross-Origin Resource Sharing)

CORS, tarayıcıların güvenlik mekanizmasıdır. Bir web sayfası, farklı bir domain'deki API'ye istek göndermeye çalıştığında tarayıcı bunu engeller — ta ki backend bu isteğe izin verene kadar.

⚠️ Sık Karşılaşılan Hata: Access to fetch at 'http://localhost:3000/api/...' from origin 'http://localhost:5173' has been blocked by CORS policy

Bu hata, frontend'iniz bir adreste (örn. localhost:5173), backend'iniz başka bir adreste (örn. localhost:3000) çalışırken ortaya çıkar. Backend'in frontend'e izin vermesi gerekir.

CORS'u Çözme (Express.js)

// Backend'de CORS izni verme
const cors = require('cors');

// Yöntem 1: Sadece belirli adreslere izin ver (ÖNERİLEN)
app.use(cors({
  origin: ['http://localhost:5173', 'https://benim-sitem.com'],
  credentials: true  // Cookie gönderimi için
}));

// Yöntem 2: Herkese izin ver (SADECE geliştirme ortamında!)
// app.use(cors()); // ÜRETİMDE KULLANMAYIN!

"Express backend'ime CORS middleware'i ekle. Geliştirme ortamında localhost:5173'e izin versin, production'da sadece https://benim-sitem.com adresine izin versin. Ortam değişkenine göre (NODE_ENV) otomatik geçiş yapsın."

Dış API Entegrasyonu İpuçları

  • API anahtarınızı frontend'de değil, backend'de kullanın (güvenlik)
  • API yanıtlarını cache'leyin (maliyet + hız)
  • Rate limit'lere dikkat edin (çoğu ücretsiz planda sınırlı istek hakkı var)
  • Hata durumlarını ele alın (API'nin çökmesi uygulamanızı çökertmemeli)

VPS'de Tipik Deployment Adımları

Bir VPS aldıktan sonra yapılacaklar:

  1. VPS'e SSH ile bağlanma (bir sonraki bölümde detaylı anlatılacak)
  2. Gerekli yazılımları kurma (Node.js, Python, nginx, PostgreSQL…)
  3. Proje kodlarını sunucuya aktarma (Git ile git clone)
  4. Bağımlılıkları yükleme (npm install veya pip install)
  5. Veritabanını ayarlama
  6. Ortam değişkenlerini yapılandırma (.env dosyası)
  7. Uygulamayı başlatma ve servis olarak tanımlama
  8. Nginx ile reverse proxy ayarlama
  9. SSL sertifikası kurma (HTTPS)
💡 Reverse Proxy Nedir? Uygulamanız genelde 3000 veya 8080 gibi bir portta çalışır. Ama kullanıcılar https://benim-sitem.com adresine (port 443) girer. Nginx, bu trafiği yakalayıp uygulamanıza yönlendirir. Buna reverse proxy denir. Ayrıca Nginx, statik dosyaları doğrudan sunarak uygulamanızın yükünü azaltır.

Sunucuda node server.js komutuyla uygulamanızı başlattığınızda, SSH bağlantısını kapattığınızda uygulama da kapanır. Uygulamanızın sürekli çalışması için onu bir servis (service) olarak tanımlamanız gerekir.

⚙️ systemd — Linux Servis Yönetimi

Linux'un yerleşik servis yöneticisi systemd, hem Node.js hem Python hem de diğer uygulamalar için çalışır. PM2'ye göre daha "düşük seviyeli" ama daha esnek ve evrenseldir.

[Unit]
Description=Benim Web Uygulamam
After=network.target postgresql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/var/www/proje
ExecStart=/usr/bin/node server.js
Restart=on-failure
RestartSec=10
Environment=NODE_ENV=production
EnvironmentFile=/var/www/proje/.env

[Install]
WantedBy=multi-user.target

        proxy_http_version 1.1;

$ certbot --nginx -d benim-sitem.com -d www.benim-sitem.com

# Otomatik yenileme testi
$ certbot renew --dry-run
✓ SSL sertifikası kuruldu! Siteniz artık HTTPS ile erişilebilir.
🎯 SSL Otomatik Yenileme: Let's Encrypt sertifikaları 90 gün geçerlidir. Certbot otomatik olarak bir cron job oluşturur ve sertifikayı süresi dolmadan yeniler. Siz bir şey yapmanıza gerek yok!

"React + Express + SQLite ile bir not defteri uygulaması yap. Her not bir başlık, içerik ve oluşturma tarihi içersin. Notları listeleme, ekleme, düzenleme ve silme olsun. Notları kategorilere ayırabilelim. Arama fonksiyonu olsun. Modern arayüz (Tailwind CSS)."

🔴 İleri Seviye — Auth + Deployment

"Next.js + Supabase ile bir blog platformu yap. Email/şifre ile kayıt ve giriş olsun. Her kullanıcı kendi blog yazılarını yazabilsin (Markdown destekli editör). Yazılar herkese açık olsun, düzenleme sadece yazara ait olsun. SEO uyumlu server-side rendering kullan."

Adım adım bir deployment script'i oluştur: 1) Node.js ve npm kur, 2) PostgreSQL kur ve veritabanı oluştur, 3) Projeyi git clone ile çek, 4) PM2 ile çalıştır, 5) Nginx reverse proxy kur, 6) Let's Encrypt ile SSL ayarla, 7) UFW güvenlik duvarını yapılandır."

"React frontend'imi Vercel'e, Express backend'imi kendi VPS'ime deploy etmek istiyorum. Frontend'de API URL'ini ortam değişkeninden okunan şekilde ayarla. Backend'de CORS'u sadece Vercel domain'ine izin verecek şekilde yapılandır. Her iki taraf için de deployment talimatlarını adım adım yaz."

🤖 İyi Prompt Yazma İpuçları:

  • Adım adım ilerleyin: Her şeyi tek seferde istemeyin, özellik özellik ekleyin
  • Hataları anlatın: "Çalışmıyor" yerine hata mesajını ve hangi adımda aldığınızı söyleyin
  • Teknik terimler kullanın: "Verileri kaydet" yerine "PostgreSQL'e INSERT yap" veya "REST API endpoint oluştur" deyin
  • Görünümü tanımlayın: "Güzel olsun" yerine "Tailwind CSS, dark mode, sidebar navigation, responsive" gibi detaylar verin

Terimler Sözlüğü Glossary

Bu ders notlarında geçen teknik terimlerin özet açıklamaları:

🌐 Web Temelleri

TerimAçıklama
HTMLWeb sayfasının yapısını tanımlayan işaretleme dili (başlıklar, paragraflar, butonlar…)
CSSWeb sayfasının görünümünü belirleyen stil dili (renkler, düzen, yazı tipleri…)
JavaScriptWeb sayfasına etkileşim katan programlama dili (tıklama, animasyon, veri gönderme…)
FrontendKullanıcının gördüğü ve etkileştiği arayüz. Tarayıcıda çalışır.
BackendSunucu tarafı: veritabanı, iş mantığı, API. Kullanıcı doğrudan görmez.
Full-StackHem frontend hem backend geliştirme yapabilme becerisi veya projesi.
APIApplication Programming Interface — programların birbiriyle iletişim kurma arayüzü.
REST APIHTTP üzerinden çalışan, URL tabanlı web API standardı.
JSONVeri alışverişi için en yaygın format. {"ad": "Ali", "yas": 25}
HTTP / HTTPSWeb iletişim protokolü. HTTPS şifreli versiyonudur (SSL/TLS).
URLWeb adresi. Örn: https://example.com/api/users
DNSAlan adlarını IP adreslerine çeviren sistem.
CORSCross-Origin Resource Sharing — farklı kaynaklardan gelen isteklerin kontrolü.
CDNİçerik Dağıtım Ağı — statik dosyaları dünya genelinde dağıtır.

🗄️ Veritabanı

TerimAçıklama
DatabaseVerilerin düzenli saklandığı sistem.
SQLYapısal veri sorgulama dili. SELECT, INSERT, UPDATE, DELETE.
NoSQLEsnek şemalı, JSON belge tabanlı veritabanları (MongoDB, Firestore).
CRUDCreate, Read, Update, Delete — 4 temel veri işlemi.
Table / TabloVeritabanında satır ve sütunlardan oluşan veri yapısı.
Primary KeyHer satırı benzersiz tanımlayan sütun (genellikle id).
Foreign KeyBaşka bir tablonun primary key'ine referans veren sütun.
ORMObject-Relational Mapping — SQL yerine programlama diliyle veritabanı yönetimi (Prisma, Sequelize).
MigrationVeritabanı şemasını sürüm kontrollü şekilde değiştirme.

🔒 Güvenlik

TerimAçıklama
AuthenticationKimlik doğrulama — "Sen kimsin?"
AuthorizationYetkilendirme — "Ne yapmaya yetkin var?"
OAuthGoogle, GitHub gibi servislerin kimlik doğrulama protokolü.
JWTJSON Web Token — şifrelenmiş kullanıcı bilgisi içeren jeton.
HashTek yönlü şifreleme — girdiyi sabit uzunlukta çıktıya dönüştürür (bcrypt).
SQL InjectionFormlardan SQL kodu enjekte ederek veritabanına müdahale saldırısı.
XSSCross-Site Scripting — sayfaya kötü amaçlı script enjeksiyonu.
SSL / TLSİnternet iletişimini şifreleyen protokol (HTTPS).
Rate LimitingBelirli sürede yapılabilecek istek sayısını sınırlama.
